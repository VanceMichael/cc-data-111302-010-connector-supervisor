# 适配器执行层：隔离边界与资源治理

本文说明采集监督进程对合作方 Node.js 适配器施加的隔离边界、各项保证的依据，以及该边界明确**不**覆盖的威胁。适配器均为本地合成实现，治理验证只使用正常输出、睡眠、无终止计算与超量日志等良性负载。

## 架构与边界

```
采集服务主进程（不加载任何合作方代码）
  └─ 每次调用：独立 Node.js 子进程，独立进程组（detached）
       ├─ stdin：协议信封 {protocol, input}，输入侧先校验再启动
       ├─ stdout：JSON Lines 业务通道，逐行协议校验
       ├─ stderr：诊断通道，字节预算 + 截断，与业务结果分离
       └─ 专属工作目录 jobs/<jobId>/attempts/<n>/，调用结束即删除
```

主进程只通过三条管道与适配器交换字节，不 `import`/`require` 合作方代码。适配器崩溃、抛异常或被信号杀死都发生在子进程内，主进程仅得到退出码、信号与受限原因。

## 预算（每次调用独立计算，可在提交时覆盖）

| 预算 | 默认值 | 实现手段 |
| --- | --- | --- |
| 时间 `timeoutMs` | 5000ms | 超时向整个进程组发 SIGTERM，宽限期后 SIGKILL |
| 业务输出 `stdoutBytes` | 4 MiB | 累计字节超限即终止，已接收行继续参与校验但永不发布 |
| 诊断输出 `stderrBytes` | 128 KiB | 超限即终止，保留预算内片段并附截断标记 |
| 内存 `memoryMb` | 128 MiB | `--max-old-space-size` 限制 V8 老生代；另以 2 倍值轮询 `/proc/<pid>/status` 的 VmRSS 作为原生内存兜底 |

## 能保证什么

1. **故障半径限于单次调用**：一个适配器死循环、睡眠或刷日志只触发自己的预算，进程组被终止；其他作业在各自子进程中继续执行，主进程不被拖住。
2. **四条硬预算**：时间、stdout、stderr、内存都有明确上限与对应的 `reason`，不会出现无限等待或无限缓冲。
3. **进程组级清理**：适配器以新进程组组长身份启动，取消/超时时向负 pid 发信号，适配器派生的孙进程同组一并回收；测试用 `child` 适配器验证了孙进程消失。
4. **输入输出双侧协议校验**：协议版本与信封结构在启动子进程前校验；stdout 逐行 JSON 解析，消息类型、`end.count` 一致性、重复 end、end 后再发 record 等均被拒绝。
5. **诊断与业务分离**：stderr 文本永远不进入记录集合；调试文本若写进 stdout，按协议违例拒绝而不是混入正式资料。
6. **失败不留半成品**：结果只有在协议完整、退出码为零后才先写暂存文件再 `rename` 原子发布到正式目录；半条记录、被终止、协议不兼容时正式目录中不会出现该作业的任何文件。
7. **取消只清理自己的作业**：删除范围通过路径前缀断言限制在本作业目录内，临时工作目录整体删除，其他作业目录与正式结果不触碰。
8. **定位式重试不重发上游请求**：原文按 SHA-256 哈希固化在 `raw/`，重试只读取本地字节并重新执行子进程；适配器脚本内容哈希与首次不一致时拒绝重试，避免静默改变解析语义。
9. **运维可见性**：每个作业持久化 `job.json`，记录状态、每次尝试的 reason、退出指标（耗时、信号、字节数、记录数）与截断诊断。

## 不能保证什么（边界之外）

1. **不是安全沙箱**：子进程与主进程以同一 UID 运行，可以访问该 UID 能访问的文件、环境变量与网络；本层不防御恶意代码，只约束资源与协议。若需要对抗不可信代码，应引入容器/微 VM（gVisor、Firecracker 等）、独立 UID/namespace 与 seccomp 策略。
2. **不限制系统调用、文件写入范围与出站网络**：适配器可以读写工作目录之外、权限允许的路径，可以发起网络连接。`cwd` 隔离只保证调用产生的临时文件有固定归集位置，不构成写屏障。
3. **内存预算是两层近似而非精确簿记**：`--max-old-space-size` 只约束 V8 老生代；RSS 轮询有 100ms 间隔且阈值取 2 倍预算，短生命周期的原生分配峰值可能短暂超过名义预算才被回收。
4. **信号回收依赖进程组语义**：适配器若主动 `setsid` 或双 fork 脱离进程组，其后代可能收不到信号；这属于有意逃逸，良性合成适配器不会这样做。
5. **不提供资源公平性/并发上限之外的调度隔离**：每个子进程独立受预算约束，但未配置 cgroup 级 CPU 配额，极端并发下机器整体 CPU 仍可能被占满；生产部署建议用 cgroup 或容器编排限制 CPU 与并发数。
6. **管道背压不是零成本的**：预算以字节计数实现有界缓冲，但在子进程被杀死前，操作系统管道与 Node 流仍会短暂持有数据；预算值决定了这部分内存的上界。
7. **不验证业务语义**：执行器只校验协议形状（record 的 value 是任意 JSON），字段级业务规则属于适配器与下游消费者的契约。

## 目录与运维

- 落盘根目录默认 `.local/runs/`，可用 `RUNS_DIR` 覆盖；包含 `raw/`（固化原文）、`jobs/<jobId>/`（job.json 与 attempts）、`out/`（仅正式结果）。
- 运维入口默认绑定 `127.0.0.1` 随机端口，可用 `OPS_HOST`/`OPS_PORT` 指定；只返回状态、原因、指标与截断诊断，不回显完整原文。
- 主进程收到 SIGTERM/SIGINT 时取消全部在执行作业并等待进程组回收后退出。
